# MedFlow PLM Agent 使用说明

## 入口与范围

本系统在原有主页新增“PLM Agent”按钮，也可以访问 `http://127.0.0.1:5180/agent`。Agent仅操作PLM的独立数据库，使用现有登录身份、业务接口和事务规则。所有者及已授权成员可使用；确认执行仍受服务端角色校验。其他系统的数据须通过既有业务消息交互，不能由本Agent直接修改。

本版具备聊天会话、数据查询、业务执行卡、提示词版本、Skill、MCP客户端、停止和审计。没有模型时显示明确标注的本系统规则摘要，不会伪装成大模型回复。

## 启动

本机已准备依赖及数据库。新机器克隆后先npm ci，再应用数据库迁移：

```powershell
cd D:\MedFlow\medflow-plm
node scripts/run-framework.mjs build
node scripts/db-local.mjs
node scripts/run-framework.mjs dev --port 5180
```

新增 `drizzle/0001_agent.sql` 只创建6张Agent表，不覆盖既有业务数据。每套应用必须绑定自己的数据库。首次未初始化应用，应先在主页完成空系统或演示初始化，再使用Agent。

## 模型配置

接口兼容Chat Completions + function tools。管理员在本系统的 `.dev.vars` 追加：

```dotenv
AGENT_MODEL_KEY=自己的模型服务API密钥
AGENT_ALLOWED_HOSTS=api.openai.com
```

重启本系统，在“提示词与扩展”填写供应商Base URL和实际模型ID。例如Base URL为 `https://api.openai.com/v1`，不要追加 `/chat/completions`。若使用其他兼容供应商，替换地址并将相应域名加入服务端白名单，多个域名用英文逗号分隔。

各套应用的配置及密钥独立保存。可以选择同一供应商，但须分别在对应项目中配置；WMS的模型配置不会自动传到本系统。密钥不能填在提示词、URL、Skill或前端代码中。模型将接收对话和工具查出的数据，选择服务前应确认数据使用范围。

本地Ollama需安装支持工具调用的模型，并在本地服务设置 `AGENT_ALLOW_LOCAL_MODEL=true`、`AGENT_ALLOWED_HOSTS=127.0.0.1,localhost`，Base URL设为 `http://127.0.0.1:11434/v1`。无需鉴权时可不填Key；云端回环地址无法访问用户电脑。真实供应商与Ollama须在用户提供凭据或环境后验收。

## 本系统业务工具

可查询的数据范围及允许动作来自 `lib/app-config.ts`，并由 `lib/agent-profile.ts` 生成工具帮助，避免混用其他系统接口。

- **工程发布检查**：核对精确组件版本、BOM循环、工序、批准文档、验证结论和独立签核。不得绕过签出人、评审人和作者分离规则。发布成功不等于MES已接收。
- **工程变更影响**：查询旧版与派生新版的BOM、工艺、文档、需求及制造反馈。说明库存、在制与客户影响，执行前要求实际变更批准和切换依据。不能伪造文档指纹、验证数据或签核身份。

建议提问：

- 检查待评审版本和未验证需求
- 查询BOM组件和版本使用关系
- 检查工程变更及MES接收回执

模型先用 `business_query` 查询真实记录，必要时读取 `business_action_help`，再用 `business_propose` 生成执行卡。操作员核对业务动作、ID、金额和完整参数后，选择确认或拒绝；确认时重新校验业务状态及所有者身份。失败结果保留，不自动重复执行。

未配置模型时也可在“业务工具”中选择数据范围、输入关键词、查看真实记录，再填写JSON参数生成执行卡。不可把示例说明文字当作业务ID。

## 跨系统消息

`integration.dispatch` 是独立的待确认动作，用于发送/重试本系统发件箱，参数为 `{}`。它调用现有发送逻辑，不绕过对端初始化、认证及业务校验。发送方保存成功不等于接收方完成；应检查消息状态、对端回执及单据。

其他系统离线时，消息会保留待发送或失败状态。通过Agent确认重试或在原“接口与消息”页面手动发送即可。相同消息ID由接收端幂等处理；本版没有自动后台调度器。

## 提示词与Skill

只有所有者可编辑系统提示词，添加、修改、启停和删除Skill，保存配置后对下一轮生效。每次保存保留版本，可恢复历史配置。Skill是业务流程说明文本，不是任意脚本执行器，也不增加用户权限。

内置业务权限、操作确认和校验不能通过提示词关闭。不得让模型编造银行回单、测温、签收人或设备到位依据。

## MCP

支持HTTPS Streamable HTTP，支持JSON及有限SSE响应；暂不支持stdio、旧独立SSE端点、OAuth自动授权。

1. 由服务器管理员将远程服务域名加入 `AGENT_ALLOWED_HOSTS`。
2. 如需Bearer令牌，在 `.dev.vars` 配置 `AGENT_MCP_TOKEN_EXTERNAL=实际令牌` 并重启。
3. 在Agent页面添加MCP地址、名称和令牌变量名，明确填写允许调用的工具名称。
4. 保存配置后点击测试连接，只有白名单工具会被发现和提供给模型。
5. 外部工具每次调用均生成确认卡，可能产生外部副作用，确认前务必核对。
6. 配置改变后旧MCP卡失效；外部超时不代表没有执行，需先核对对端，不自动重试。

禁止把实际令牌作为变量名填进页面。网络白名单需配合生产出口控制，不能代替完整网络隔离。

## 权限、状态与限制

本系统支持所有者和已授权成员。所有者管理模型、提示词、Skill及MCP，普通成员可使用查询与执行卡；确认操作仍由原业务角色及状态机校验。例如只读成员不能通过Agent写入业务，PLM签核人仍必须与作者不同并被指定。未登录、未授权或未初始化不能使用Agent。所有写API要求同源请求，会话、卡片和Agent审计按身份隔离。

停止会话不能撤销已完成的操作。进程中断后可点停止解锁会话；执行卡若停在running，需要核对原业务请求与外部状态，本版不自动恢复。外部MCP不保证业务幂等。

没有Windows桌面控制、任意命令行、文件访问、后台调度、流式逐字输出、跨系统总控或通用插件市场。不能以本次集成声称已达到所有商业Agent产品的完整程度。当前仍为开发验证环境。

## 检查与测试

```powershell
npm run test:agent
npm run typecheck
npm run build
```

Agent测试使用内存数据库和模拟模型/MCP传输，检查策略、配置版本、会话锁、工具确认与业务幂等。浏览器检查脚本为 `tests/browser.mjs`，需额外准备Playwright及浏览器，通过PLAYWRIGHT_MODULE和AGENT_TEST_BROWSER环境变量指定；不将个人电脑路径写入源码。

## 发布与备份

源码、数据库迁移、测试与本文档可提交Git。不要提交 `.dev.vars`、密钥、`.wrangler` 数据库、`.sites-runtime` 截图与会话。生产发布先备份、迁移再上线；本次本地修改不会自动更新GitHub和云端站点。
