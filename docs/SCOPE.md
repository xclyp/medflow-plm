# 能力与交付边界

这是两套独立、有服务端业务规则和持久化的功能开发版本，不是仅展示静态数据的页面。通过功能测试不等于已经完成任意工厂的投产验证，也不承诺在没有选定对标产品和验收条件时“全面媲美大多数商用系统”。

## 已实现的通用闭环

- MES：资料/工艺 → 工单 → 批次待检与放行 → 预留/领退料 → 顺序工序执行与报工 → 过程/终检 → NCR处置与返工 → 完工 → 序列及批次履历。
- PLM：物料/版本 → 签出设计 → 多层BOM/工艺/文档 → 需求验证 → 独立多评审签核 → 冻结发布 → ECR/ECO → 新版生效与实施。
- 协同：PLM发布包 → MES工艺快照 → 接收确认 → 完工反馈，使用独立数据库、服务凭据和消息幂等。
- Agent：本域查询与确认执行、角色校验、提示词版本、文本Skill、HTTP MCP白名单、会话和审计。

## 明确未实现的专业扩展

| 项目 | 当前边界 |
| --- | --- |
| 行业生产模型 | 面向一般离散装配；连续流程/配方反应、联副产品、替代料、批次拆并和复杂返修路由需要扩展 |
| 排程 | 手动有限设备时段与冲突/标准工时检查；没有优化APS求解器或拖拽甘特调度 |
| 数据采集 | 人工/PDA键盘输入；没有PLC、OPC UA、MQTT、SCADA适配器或设备自动报工 |
| 质量统计 | 结构化检验数量和依据、NCR闭环；未实现完整SPC/MSA/FMEA/APQP、量具校验和实验室LIMS |
| 文档工程 | PLM可上传下载10MB以内原文件，保存指纹；没有CAD内核、3D查看、图纸红线/像素比较、自动格式转换 |
| BOM与成本 | 精确多层组件版本、损耗展开、对比和where-used；没有配置式150% BOM、选配求解和完整成本卷积 |
| 集团平台 | 每套数据库对应一个工作空间，工作中心和项目可多个；没有租户级多集团、多法人隔离 |
| 身份与合规 | 服务端角色和独立评审；开发登录仅回环模拟。生产SSO、合规电子签名、审计防篡改存储需实施 |
| 运营保障 | 事务、CAS、请求/消息幂等、审计；无高可用部署、长期压测、分库和日志监控平台 |
| 消息运营 | 人工或Agent确认发送/重试；没有后台调度、定时重试、死信工作流和跨系统分布式补偿 |
| Agent扩展 | 文本Skill与HTTPS Streamable HTTP MCP；没有任意终端执行、stdio MCP、OAuth自动授权、无限后台自治 |
| 外部系统 | 已定义MES/PLM三种事件；原六套系统未自动增加新事件消费者 |

## 真实上线所需验收

按实际工厂选择生产模式、单位精度、批次/序列规则、班次和质量标准；补齐现场设备/ERP/WMS接口，完成真实身份认证、备份恢复、异常与性能验收、现场培训。真实文档和生产数据不应直接使用演示环境。开发模式不能作为对公网开放的生产认证。

## 数据规模

当前存储将业务集合读入内存，通过受控事务批量保存差异。适合功能验证和小规模试运行；持续大量报工、长期审计和并发操作需要服务端查询分页、归档与负载评估。UI分页不是服务器存储容量或并发性能的承诺。

删除/移动项目之前停止服务，并保留数据库、PLM文件库、密钥和对应源码版本的一致备份。单独备份CSV或压缩源码不能恢复全部业务。
