# MedFlow PLM · 产品生命周期系统

独立运行的通用产品生命周期应用，包含服务端业务校验、独立数据库、消息收发、角色权限和可配置Agent。面向离散制造及一般装配场景，不限定医药行业。本次为可运行的功能开发版本，不以模块数量宣称已达到任意商用产品的全部能力。

## 功能范围

| 领域 | 已实现 |
| --- | --- |
| 产品数据 | 产品、装配件、自制件、采购件与原料，统一编码和单位 |
| 版本 | 创建/派生、签出/签入、草稿编辑、提交、批准、发布、生效与作废 |
| BOM | 精确组件版本、多层结构、循环检查、位号/用量/损耗、反向使用关系 |
| 工艺 | 工序号、工作中心编码、单件标准工时、作业指导和过程检验要求 |
| 文件库 | 真实文件上传/下载、自动SHA-256、独立R2文件存储、外部HTTPS文档登记 |
| 评审 | 作者与评审人分离、多评审人一致同意、拒绝退回、逐轮签核记录 |

## 本机启动

本机路径：`D:\MedFlow\medflow-plm`。数据库与文件库在本项目忽略目录 `.wrangler/state`；运行缓存位于 `.sites-runtime`、`.vinext`，未在C盘安装另一份项目。

双击 `启动PLM.cmd`，或在PowerShell执行：

```powershell
cd D:\MedFlow\medflow-plm
$env:RAYON_NUM_THREADS='1'
node scripts/run-framework.mjs dev --port 5180
```

打开 [系统主页](http://127.0.0.1:5180/) 或 [Agent](http://127.0.0.1:5180/agent)。终端窗口需保持打开；Ctrl+C停止。若已有本系统服务运行，直接访问，不重复启动。

首次点击登录是**本地模拟登录**，默认 `seedy@sites.test`，不需要ChatGPT账号或模型Key。登录后选择空系统或演示资料初始化；重复初始化会被拒绝。演示资料不可当作真实生产和签核依据。

## 新电脑部署

依赖Node.js 22.13及以上，推荐22 LTS；Windows PowerShell或Linux均可，浏览器使用现代Edge/Chrome。源码不含node_modules及个人密钥。

```powershell
cd 项目目录
npm ci
npm run typecheck
npm test
npm run build
npm run db:local
node scripts/run-framework.mjs dev --port 5180
```

当前电脑复用了D盘依赖目录的junction；**不要对现有junction执行npm ci**，避免覆盖其他MedFlow项目共享依赖。新电脑普通克隆没有此junction，可以正常npm ci。

`npm run start -- --port 5180` 可运行构建后的本地Worker；它不包含开发模拟登录，必须配置可信认证网关后使用。不要通过直接伪造认证头把开发模式当作生产认证。

## 操作指南

1. **主档和版本**：建立物料，创建设计版本并签出。已发布版本只允许派生新版，不能原地修改。
2. **设计**：编制精确组件版本BOM、工艺路线；BOM组件须先发布。演示采购组件已标记为演示发布状态。
3. **文件与验证**：上传真实文件或登记企业文档库地址。批准必要文档，维护需求并录入真实试验结论。文件SHA-256可自动算；外部文件手填指纹仅是登记，不代表服务端已经下载验证。
4. **独立评审**：所有者先授权reviewer成员。签入设计，指定作者以外的评审人提交。所有指定人签核同意后版本状态变为approved。
5. **发布**：所有者选择生效日期发布，形成冻结基线；未来日期版本不能提前发送MES。
6. **工程变更**：从已发布旧版派生新版，创建ECR/ECO，填写库存/在制/客户影响处置；变更批准、新版评审批准后才能发布新版，生效后再确认实施。
7. **制造协作**：发送制造发布包；MES需有对应工作中心编码。检查接收回执，生产完工后反馈归档到原设计版本。
8. **检索比较**：“分析与追溯”可展开BOM树、查询上级引用，选择同物料另一版本比较BOM、工艺与文档。

## 账号与权限

初始化者是所有者。所有者在“成员与权限”登记实际登录身份，例如 `email:reviewer@company.com`。成员只能查看本应用资料，修改权限由服务端角色表校验；停用即拒绝访问。所有者管理成员、集成与Agent模型/MCP配置。普通成员可以使用Agent，但确认执行仍受其原业务角色约束。

角色：设计工程师（设计/签出签入/BOM/工艺/文档/需求/变更/项目任务）、独立评审人（指定签核/验证记录）、只读。所有者执行发布等管理动作。评审人必须与版本/变更作者不同。

本地多角色验证：先用默认所有者授权 `email:reviewer@sites.test` 等成员，再在另一浏览器窗口打开：

```text
http://127.0.0.1:5180/signin-with-chatgpt?dev_email=reviewer@sites.test&return_to=/
```

`dev_email` **仅用于回环地址的开发服务器**。每次生成独立随机会话Cookie，用户输入的认证头会被清除；重启后重新登录。返回默认所有者时不带dev_email。生产构建不包含模拟身份选择，需接入组织SSO和可信认证边界。

## MES与PLM协作

详见 [接口与联调](docs/INTEGRATION.md)。本机已配置两套应用的本地通信地址与随机服务凭据，密钥只在各自忽略的 `.dev.vars` 中。新机器两套项目放在同级后运行：

```powershell
node scripts/link-local.mjs
```

脚本只连接MES/PLM，不覆盖不一致的既有密钥。配置变更后重启两套服务。消息采用发件箱/收件箱与幂等处理；本版由人工或Agent确认发送，没有常驻后台消息调度器。

原六套WMS/OMS/ERP/BMS/TMS/WCS未被改写；**新系统并未自动完成与那六套的全部接口适配**。接入需按接口契约补齐双方领域事件、认证与主数据映射。

## Agent

见 [Agent配置与使用](docs/AGENT.md)。模型兼容OpenAI格式Chat Completions及函数工具调用；模型名、Base URL在页面配置，API Key只在服务端环境配置。没有模型Key时仍可查询和使用手动确认卡，规则摘要会明确标注。

## 质量与部署边界

见 [能力与交付边界](docs/SCOPE.md) 及 [验证记录](docs/VALIDATION.md)。通用核心流程已实现；现场PLC/设备协议、CAD解析预览、复杂APS、多组织隔离、电子签名合规及高并发生产规模需要单独工程实施。本仓库不将这些未实现能力展示成可用按钮。

生产启用前，需完成真实身份认证、独立数据库/文件库绑定、备份恢复演练、业务验收和真实设备/外部服务联调。每次升级先备份，再构建与应用新增迁移；禁止用演示初始化覆盖数据。

## 技术栈与结构

TypeScript、React 19、Vinext/Vite、Cloudflare Worker、D1/SQLite、Drizzle、R2独立文件库、Lucide。没有Java或Spring后端。

- `lib/domain.ts`：本系统状态机及业务规则。
- `lib/service-store.ts`：D1事务、权限、幂等、审计、比较交换。
- `lib/app-config.ts`：业务区域、表单与工具契约。
- `app/console.tsx`：工作台、结构化明细录入、搜索导出。
- `components/manufacturing-insights.tsx`：业务看板及结构/追溯分析。
- `lib/agent-*.ts`、`app/agent`：Agent工具、会话、模型及MCP。
- `drizzle`：业务及Agent数据库迁移。
- `tests`：领域、持久化、权限和Agent回归测试。

## 备份与故障排查

停止服务后备份整个项目的 `.wrangler/state`（含D1数据库及R2文件对象）及单独保管 `.dev.vars`。恢复时用同版本源码、数据库和文件对象一起恢复。仅导出CSV不能恢复版本基线、审计和文件库。

- “请先登录”：访问页面上的登录链接；开发服务器重启会清除本地模拟会话。
- “数据库表不存在”：先build，再执行db:local，不要重复初始化已有业务。
- “账号未授权”：用所有者登录，为当前真实身份授权对应角色。
- “工作中心不存在”：在MES新增与PLM工艺一致的工作中心编码后重试原消息。
- “需先签出”：以设计人员身份签出草稿后编辑；发布版本只能派生。
- Agent仅显示规则摘要：尚未配置模型名、服务端密钥或供应商域名白名单。
- 内存不足：只启动需要的应用，设置RAYON_NUM_THREADS=1，顺序构建。
